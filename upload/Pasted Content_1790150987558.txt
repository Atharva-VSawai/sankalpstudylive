55. FINAL IMPLEMENTATION RULE
==================================================

Do not add features simply because they are listed here if the existing architecture cannot support them correctly.

Prefer:

REAL + FUNCTIONAL + SERVER-AUTHORITATIVE

over:

FAKE + VISUALLY IMPRESSIVE

If a feature cannot currently be fully implemented because the sandbox uses simulated infrastructure, implement the UI and correct architecture only where appropriate and clearly label the limitation.

Do not fabricate production data.

Do not fake payments.

Do not fake analytics.

Do not fake LiveKit health.

Do not fake Redis health.

Do not fake email delivery.

1. Run lint.
2. Run existing tests.

4. Browser-test the complete admin flow.

7. Verify all sensitive actions generate AuditLog entries.
8. Verify existing user-facing functionality remains intact.
